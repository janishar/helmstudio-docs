Pick the way that fits your machine:

| Machine | How |
|---|---|
| Mac with Apple Silicon | [The Mac app](#mac-the-app). No Docker needed. |
| Windows | [Docker Desktop](#windows-and-linux-with-docker), with WSL2 |
| Linux | [Docker](#windows-and-linux-with-docker) |

Every release is on [GitHub releases](https://github.com/janishar/helmstudio/releases). Models are not included:
download them on the [Models](/studio/models/) screen. Each keeps its own licence.

## Mac: the app

<Steps>

1. Download `helmstudio-0.1.0-alpha.5.dmg` from the [release](https://github.com/janishar/helmstudio/releases).

2. Open it and drag **helmstudio** to Applications.

3. The app is ad-hoc signed: the first time, right-click it › **Open**, then **Open** again.

4. The first open sets everything up in one window and asks for your admin account.

</Steps>

Already on 0.1.0-alpha.2 or 0.1.0-alpha.3? Choose **Check for updates…** in the app's menu, then **Install**. Your
work and settings stay. From 0.1.0-alpha.1, replace the app by hand once.

Every step, the menu bar and updates: [The Mac app](/start/mac-app/).

## Windows and Linux with Docker

Each release has one file, `compose.yml`, that runs the release's images. Nothing to build and no install script.
The images are made for Intel/AMD and ARM machines.

<Aside type="caution" title="Windows is untested">
  The Windows steps follow Docker Desktop's normal setup, but they have not been tried yet. Please
  [report what breaks](https://github.com/janishar/helmstudio/issues).
</Aside>

You need Docker with Compose 2.26 or later, about 3 GB of disk for the images (plus your models) and 2 GB of memory.

<Tabs>
  <TabItem label="Windows">

<Steps>

1. Install [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) with the WSL2 backend
   (its default) and start it.

2. Open PowerShell, make a folder and download the release's `compose.yml` into it:

   ```powershell
   mkdir helmstudio; cd helmstudio
   curl.exe -LO https://github.com/janishar/helmstudio/releases/download/v0.1.0-alpha.5/compose.yml
   ```

3. Beside `compose.yml`, add a file named `.env` with your admin account (a password of 10 characters or more):

   ```powershell
   Set-Content -Encoding ascii .env @"
   HELMSTUDIO_ADMIN_EMAIL=you@example.com
   HELMSTUDIO_ADMIN_PASSWORD=choose-a-long-password
   "@
   ```

4. In the same folder, start it:

   ```powershell
   docker compose up -d --wait
   ```

5. Open `http://localhost:8300` and sign in.

</Steps>

  </TabItem>
  <TabItem label="Linux">

<Steps>

1. Install [Docker Engine](https://docs.docker.com/engine/install/) with the Compose plugin, or Docker Desktop.

2. Make a folder and download the release's `compose.yml` into it:

   ```sh
   mkdir helmstudio && cd helmstudio
   curl -LO https://github.com/janishar/helmstudio/releases/download/v0.1.0-alpha.5/compose.yml
   ```

3. Start it the first time with your admin account:

   ```sh
   HELMSTUDIO_ADMIN_EMAIL=you@example.com HELMSTUDIO_ADMIN_PASSWORD='10 characters or more' docker compose up -d --wait
   ```

4. Open `http://localhost:8300` and sign in.

</Steps>

  </TabItem>
</Tabs>

The first start makes the stack's secrets and your admin account. The admin is read on the first start only: after
that, `docker compose up -d` is enough, and a password you change in the app's [Settings](/studio/settings/) is kept.
There is no public sign-up: add other people in [System](/studio/system/) › **Users**.

Every port is on `127.0.0.1`. To reach the studio from another machine, use an SSH tunnel or a reverse proxy, and set
`PUBLIC_BASE_URL` and `WEB_COOKIE_SECURE` (see [Settings](#settings)).

This stack has no model runner of its own. Without an NVIDIA runner the studio opens (the Assistant, the Gallery,
editing pipelines, uploads) but cannot make takes: add one as in [An NVIDIA card](#an-nvidia-card). On a Mac, use the
[Mac app](#mac-the-app) instead.

### Update

Download the new release's `compose.yml` over the old one, then:

```sh
docker compose pull
docker compose up -d --wait
```

Your data and keys stay in Docker volumes. `docker compose down` stops everything and keeps them;
`docker compose down -v` deletes them too.

### Settings

Put these in `.env`, beside `compose.yml`:

| Name | Default | What |
|---|---|---|
| `HELMSTUDIO_PORT` | 8300 | The studio's port on `127.0.0.1` |
| `PUBLIC_BASE_URL` | `http://localhost:8300` | The address people open |
| `WEB_COOKIE_SECURE` | false | `true` behind TLS |
| `REMOTE_MODELS` | off | `on` allows remote model providers, such as OpenAI |
| `HELMSTUDIO_GPU_HOST` | gpu | The NVIDIA runners' host name. Set it before the first start. |
| `HELMSTUDIO_VERSION` | the file's release | Run another release's images |
| `HELM_NET` | 172.30.97 | The stack network's first three numbers, if they clash with yours |

## An NVIDIA card

No NVIDIA image ships. The stack runs in Docker as usual, and the GPU runners run on the machine itself, from a clone
of the repository, on the card's own driver. Run the stack either way:

- **The Docker stack**: the release's `compose.yml`, started as in [Windows and Linux with Docker](#windows-and-linux-with-docker).
  Its NVIDIA host is named `gpu`.
- **From source**: `make up GPU_HOSTS=<h>` in the clone. The host is named `<h>`.

<Tabs>
  <TabItem label="Linux">

<Steps>

1. Install the NVIDIA driver with its tools, recent enough for CUDA 13. `nvidia-smi` must work. On Ubuntu, for
   example:

   ```sh
   sudo apt install nvidia-headless-no-dkms-595-server-open \
     linux-modules-nvidia-595-server-open-$(uname -r | sed 's/.*-//') nvidia-utils-595-server
   sudo reboot
   ```

   A headless driver alone has no `nvidia-smi`: `nvidia-utils` adds it. If `apt` downloads crawl, switch to
   `http://archive.ubuntu.com/ubuntu` in `/etc/apt/sources.list.d/ubuntu.sources`.

2. Install Docker with Compose 2.26 or later, and the tools:

   ```sh
   sudo apt install git make ffmpeg
   ```

3. Install uv 0.13.8. It goes into `~/.local/bin`, so put that on your `PATH`:

   ```sh
   curl -LsSf https://astral.sh/uv/0.13.8/install.sh | sh
   export PATH="$HOME/.local/bin:$PATH"
   ```

   A script or an SSH command does not read your login profile. Without that `PATH`, `make runners-nvidia` fails
   with "uvx: No such file or directory". No CUDA toolkit is needed: the runner's PyTorch brings its own CUDA
   libraries.

4. Clone the repository:

   ```sh
   git clone https://github.com/janishar/helmstudio.git
   cd helmstudio
   ```

5. Start the runners. Point `HELMSTUDIO_MODELS` at your models folder (default `~/GenAI/models`).

   With the Docker stack already running:

   ```sh
   HELMSTUDIO_MODELS=~/models make runners-nvidia STACK=release
   ```

   This copies host `gpu`'s runner credentials out of the stack into `deploy/secrets-release/`. If you set
   `HELMSTUDIO_GPU_HOST` in `.env`, add `GPU_HOST=<that name>`.

   From source instead: run `make envs`, set `ADMIN_EMAIL` and `ADMIN_PASSWORD` in `auth_service/.env` (see
   [From source](#from-source)), then:

   ```sh
   make up GPU_HOSTS=gpu1
   GPU_HOST=gpu1 HELMSTUDIO_MODELS=~/models make runners-nvidia
   ```

   A host name is short: lower-case letters and digits.

6. Open `http://localhost:8300`. The first start downloads PyTorch's CUDA libraries (a few GB). The host shows in
   [System](/studio/system/) › **Hosts** only after that.

</Steps>

  </TabItem>
  <TabItem label="Windows (WSL2)">

<Aside type="caution" title="Untested">
  Nobody has run this on Windows yet. Please [report what breaks](https://github.com/janishar/helmstudio/issues).
</Aside>

<Steps>

1. Install the NVIDIA driver on **Windows** only. WSL2 passes the card through, so `nvidia-smi` works inside it. Do
   not install a Linux driver inside WSL2.

2. Install [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) with the WSL2 backend.
   In **Settings › Resources › WSL integration**, turn it on for your Ubuntu, so `docker` works inside WSL2.

3. Install Ubuntu 24.04 in WSL2 (PowerShell):

   ```powershell
   wsl --install -d Ubuntu-24.04
   ```

4. Inside Ubuntu, follow the Linux steps from step 2 on: `git make ffmpeg`, uv, the clone and
   `make runners-nvidia`, and SGLang if you want it.

5. Keep the repository and the models on WSL2's own disk (for example `~/helmstudio` and `~/models`), not under
   `/mnt/c`: the Windows drive is much slower from WSL2.

6. Open `http://localhost:8300` in a Windows browser.

</Steps>

  </TabItem>
</Tabs>

### MiniMax H3 video: SGLang (optional)

MiniMax H3 video on NVIDIA (**Base fp8**) needs SGLang 0.5.23, in its own environment. On the stack's own machine
this works on Linux x86_64 (Intel/AMD) only. In the clone:

<Steps>

1. Install a C compiler and Python's headers. SGLang compiles GPU kernels on its first run.

   ```sh
   sudo apt install build-essential python3.12-dev
   ```

2. Make SGLang's environment and add the two CUDA links it needs:

   ```sh
   uv venv --python 3.12 ~/sglang
   VIRTUAL_ENV=~/sglang uv pip sync runner_service/sglang-requirements.txt
   (cd ~/sglang/lib/python3.12/site-packages/nvidia/cu13 && ln -s lib lib64 && ln -s libcudart.so.13 lib/libcudart.so)
   ```

3. Start the runners again with `SGLANG_BIN` set: add `STACK=release` with the Docker stack, or `GPU_HOST=<h>` from
   source. The runner that is already up keeps running, and the `native` runner starts too.

   ```sh
   SGLANG_BIN=~/sglang/bin/sglang HELMSTUDIO_MODELS=~/models make runners-nvidia
   ```

</Steps>

The first video takes a few minutes longer while SGLang compiles.

### On a cloud machine

- Give it a short hostname. A long one (a cloud VM's full internal name) stops SGLang starting with "File name too
  long":

  ```sh
  sudo hostnamectl set-hostname gpu1
  ```

- To use the studio from another computer, tunnel the same port, then open `http://localhost:8300` there:

  ```sh
  ssh -N -L 8300:127.0.0.1:8300 <host>
  ```

  Sign-in works only at the studio's own address, so a different local port fails. To use another address, set
  `PUBLIC_BASE_URL` (and `HELMSTUDIO_PORT`) in `.env`.

### Logs and stopping

Each runner logs to `runner_service/.run/runner-<host>-<env>.log`. Stop the runners with
`make runners-nvidia-stop` (add `STACK=release` with the Docker stack), then the stack with `make down` or
`docker compose down`.

### What runs on NVIDIA

| Model | This machine | [A separate NVIDIA host](/start/hosts/#a-separate-nvidia-host) |
|---|---|---|
| Qwen Image 2.1, LTX-2.5, Qwen3-TTS | Yes | Yes |
| MiniMax H3 Image | Yes, as **Base fp8** | Yes, as **Base fp8** |
| MiniMax H3 (video) | **Base fp8**, with [SGLang](#minimax-h3-video-sglang-optional) | **Base fp8**, with the `native` runner |
| ZONOS3 | Not yet (needs a CUDA toolkit build) | Yes, with the `native` runner |
| Ask | Qwen3-VL 8B | Qwen3-VL 8B |
| Ask's local LLM (Qwen3.8 27B) | No: Macs only | No: Macs only |

The Turbo LoRA does not work on MiniMax H3 Base fp8 yet.

## From source

For developers: the services in Docker, the model runners native on the machine so they can use its GPU. To keep a
stack running for real work on a Mac, see [Run in production on a Mac](/start/production/). On Linux with an NVIDIA
card, see [An NVIDIA card](#an-nvidia-card).

### Requirements

- A Mac with Apple Silicon, or Linux (with an NVIDIA card to make takes). On Windows, only inside WSL2.
- Docker with Compose 2.20 or later (OrbStack or Docker Desktop).
- `make` and `openssl`.
- For the native runners on a Mac: [uv](https://docs.astral.sh/uv/), the Xcode Command Line Tools, CMake and Rust
  (`cargo`). On Linux, see [An NVIDIA card](#an-nvidia-card).
- For the `helm` command-line client: Go.
- Model weights on disk. See [Models](/models/).

### Start the stack

<Steps>

1. Clone the repository.

   ```sh
   git clone https://github.com/janishar/helmstudio.git
   cd helmstudio
   ```

2. Make the `.env` files from their examples.

   ```sh
   make envs
   ```

3. Set the admin account. Open `auth_service/.env` and fill in `ADMIN_EMAIL` and `ADMIN_PASSWORD`. This is the only
   admin. There is no public sign-up: the admin creates every other account.

4. Build and start the stack.

   ```sh
   make up
   ```

   The first run makes the secrets in `deploy/secrets/`, builds the images, starts every service and waits until all
   of them are healthy.

5. Open the studio at `http://localhost:8300` and sign in as the admin.

6. Add accounts for other people in [System](/studio/system/) › **Users**.

</Steps>

<Aside>
  The admin password from `auth_service/.env` is set only when the account is first made. After that, change it in
  the app's [Settings](/studio/settings/).
</Aside>

The local stack also runs a small test host with an Echo workflow, so you can try the studio before any model is
installed. Real models need the native runners below.

### Start the native runners

The runners are the processes that load models and make takes. On a Mac there are three, each in its own process:

| Runner | Runs |
|---|---|
| `torch` | PyTorch on the Mac's GPU: Qwen Image, MiniMax H3 Image, Qwen3-TTS |
| `mlx` | MLX: LTX-2.5 and the local text models |
| `native` | Native binaries: MiniMax H3 video and ZONOS3 |

Start all three in the background:

```sh
make runners
```

They read weights from the folder in `HELMSTUDIO_MODELS` (default `~/GenAI/models`). Set it to your models folder
when you start them:

```sh
HELMSTUDIO_MODELS=~/helmstudio-models make runners
```

`make runners` builds the native binaries the first time; that takes a couple of minutes. You can also start one
runner on its own with `make runner-torch`, `make runner-mlx` or `make runner-native`.

Each runner writes a log to `runner_service/.run/runner-mac-<env>.log`. A runner that stalls or is stopped by the
system restarts on its own. Once they are up, the Mac shows as host `mac` in [System](/studio/system/) › **Hosts**.

Stop them with:

```sh
make runners-stop
```

### Daily commands

| Command | What it does |
|---|---|
| `make up` | Build and start the stack, wait until healthy |
| `make down` | Stop the stack. Your data stays. |
| `make logs` | Follow every service's logs |
| `make logs s=studio` | Follow one service's logs |
| `make ps` | Show what is running |
| `make runners` | Start the native runners |
| `make runners-stop` | Stop the native runners |

### Ports

Everything is published on `127.0.0.1` only. The ports are set in `deploy/.env`.

| Port | What |
|---|---|
| 8300 | The studio and its API (`KONG_HTTP_PORT`) |
| 5463 | Postgres (`POSTGRES_HOST_PORT`) |
| 4322 | NATS, for the native runners (`NATS_HOST_PORT`) |
| 8433 | The object store, for the native runners (`S3_HOST_PORT`) |
