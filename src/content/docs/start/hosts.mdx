A **host** is a machine with model runners. A **runner** is a process that loads a model's weights and makes takes.
The studio's services can run on one machine while the runners run on several.

## Macs

A Mac with Apple Silicon is one host, named `mac`. It runs three runners, each in its own process:

- `torch`: PyTorch on the Mac's GPU.
- `mlx`: MLX.
- `native`: native binaries, such as MiniMax H3 video and ZONOS3.

On a Mac the CPU and GPU share one memory. So the three runners share **one memory budget**: the Mac's memory minus a
reserve. Before a run starts, the studio checks that the run's planned peak, plus everything already loaded on the
host, fits the budget. If it does not, the studio asks the runners to unload the least recently used parts, and the
run waits until they have.

The Mac app starts its runners itself. From source, start them with `make runners`. See [Install and run](/start/install/).

## NVIDIA hosts

A Linux machine (or Windows with WSL2) with an NVIDIA GPU joins as one more host. Its runners run on the machine
itself, on the card's own driver: the `torch` runner, and a `native` runner for MiniMax H3 video when SGLang is
installed. Its budget is the GPU's memory minus a reserve. Set it up as in
[An NVIDIA card](/start/install/#an-nvidia-card).

Some model variants run on one kind of host only:

| Only on a Mac | Only on NVIDIA |
|---|---|
| LTX-2.5 Distilled and Dev, MiniMax H3 Base video, Qwen3.8 27B | Every fp8 and int8 community variant |

Each family's page under [Models](/models/) lists its variants.

## Where a run goes

On Create, **Run on** picks the host:

- **Auto** sends the run to an eligible host: one that has the runner, the weights and the memory. It prefers a host
  that already has the model loaded.
- **A named host** sends it there only. A run set to a host never moves.

A host that cannot take the run is greyed out, with the reason. Generate shows the run's estimated time and peak
memory. A run too big for every host fails at once and says why.

Each host does **one run at a time**. Other runs wait in a queue, in order. If a host goes offline during a run, the
run is tried once more on another eligible host, or it fails with the reason.

## Memory settings

An admin sets each host's memory in [System](/studio/system/) › **Hosts**. The settings apply to every runner on that host.

| Setting | What it does |
|---|---|
| After the queue drains | **Unload everything** stops the runner processes, the only way to be sure memory goes back to the system. **Keep warm** keeps models loaded until memory is needed or the idle timeout passes. **Keep pinned only** keeps pinned parts and unloads the rest. |
| Idle timeout, minutes | How long Keep warm waits before unloading. 0 means never. |
| Memory reserve, GB | Memory kept back for everything else. The budget is the host's memory (the GPU's memory on NVIDIA) minus this. |
| Pins | Keep a model part loaded between runs. |

The same settings are available from the command line:

```sh
helm hosts                                         # each host's memory, device, runners and what they hold
helm hosts after-run <host> keep_warm --idle-min 10 --reserve-gb 12
helm hosts unload <host> --all
```

See [The helm CLI](/mcp/helm-cli/) for the rest.

## Add an NVIDIA host

An NVIDIA machine runs the stack in Docker and its runners on the machine itself, from a clone of the repository. Every
step is in [An NVIDIA card](/start/install/#an-nvidia-card), for Linux and for Windows with WSL2.

- With the Docker stack the host is named `gpu` (`HELMSTUDIO_GPU_HOST` in `.env` names it otherwise). From source it
  is the name you give `make up GPU_HOSTS=<h>`.
- [System](/studio/system/) › **Hosts** lists the host with its GPU and memory once its runners are up. Download models
  to it in [Models](/studio/models/), or with `helm model pick --host <h>`.
- To stop the host cleanly, run `make runners-nvidia-stop` on it. A host that drops off goes offline after about 30
  seconds.

<Aside type="caution">
  The stack publishes its message bus (NATS) and object store on `127.0.0.1` only. Never publish them to the internet.
</Aside>
